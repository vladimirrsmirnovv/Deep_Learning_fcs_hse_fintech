# Домашка: свой LLM-клиент и кодовый агент

Это практическое продолжение семинара 12 («Агенты, tool calling и кодовые агенты»).
Вы своими руками соберёте то, что на семинаре было «под капотом»: синхронный клиент
к LLM с поддержкой вызова инструментов и кодового агента поверх него.

Домашка состоит из **двух частей по 100 баллов** (всего 200).

---

## Часть 1 — LLM-клиент с tool calling (100 баллов)

Файл: **`llm_client.py`**.

Нужно реализовать синхронный клиент к OpenAI-совместимому Chat Completions API
**поверх сырого `requests`** и весь «ручной» tool calling вокруг него:

- `LLMClient` — POST на `{base_url}/chat/completions` с заголовком `Authorization: Bearer ...`
  и телом `{model, messages, temperature, max_tokens}`; метод `chat(messages) -> str`.
- `render_tools_system_prompt(schemas)` — собрать system prompt со списком инструментов
  и инструкцией формата вызова (Qwen-style `<tool_call>{...}</tool_call>`).
- `parse_tool_calls(text)` — вытащить все `<tool_call>{...}</tool_call>` и распарсить JSON.
- `execute_tool_calls(calls, tools)` — исполнить вызовы, аккуратно обработав ошибки
  (неизвестный инструмент, неверные аргументы, исключение в инструменте).
- `wrap_tool_response(result)` — обернуть результат инструмента для следующего хода модели.
- `run_tool_loop(...)` — цикл «модель → парсинг → исполнение → ответ → повтор».

### ⚠️ Ограничения Части 1

- **Нельзя** использовать библиотеку `openai` — только `requests`.
- **Нельзя** использовать нативный function-calling: параметры `tools=` / `functions=`
  **не должны** уходить в тело запроса. Формат вызова инструментов вы описываете
  в system prompt сами и парсите ответ модели руками.

Тесты Части 1 детерминированы и работают против локального mock-сервера — реальная
модель, ключ и сеть не нужны.

> 💡 **Идея для самопроверки (необязательно).** OpenAI-совместимый API возвращает
> поле `usage` (`prompt_tokens` / `completion_tokens` / `total_tokens`) в каждом
> ответе. Можете копить его в `LLMClient` и смотреть, сколько токенов «стоит» ваш
> агент на одной задаче — полезная привычка при работе с агентами.

## Часть 2 — кодовый агент + мини-SWE-bench (100 баллов)

Файлы: **`tools.py`** и **`agent.py`**.

Поверх клиента из Части 1 вы соберёте кодового агента с файловыми инструментами.

- `tools.py` → класс `FileTools(workdir)` с инструментами в песочнице: `read_file`
  (с номерами строк, `offset`/`limit`), `write_file`, `edit_file` (замена по **точному
  уникальному** совпадению `old → new`), `list_files` и **`run_tests`** (прогнать
  pytest в рабочей директории и увидеть трейсбек). Все пути — строго внутри `workdir`.
- `agent.py` → класс `CodeAgent(client, workdir, max_steps)` с методом `run(task) -> str`:
  agent loop, который читает/правит файлы, **запускает тесты** и сам решает, когда
  остановиться.

Оценивается агент на **мини-SWE-bench**: наборе курируемых задач, где в маленьком
проекте (иногда из нескольких файлов) есть баг. **Описания ошибки агенту не дают** —
промт generic «почини, чтобы тесты проходили»; агент сам запускает `run_tests`,
читает трейсбек и итеративно чинит исходники. Тесты лежат в песочнице, но **править
их нельзя**: грейдинг идёт по эталонной копии тестов в чистой папке (правка тестов
или подкинутый `conftest.py` не засчитываются). Скор = `% решённых задач`:

- `>= 50%` решённых → **50 баллов**;
- `>= 70%` решённых → **ещё +50 баллов**.

Для прогона агента нужна реальная модель. Курс размещает её для вас на собственном
сервере (vllm) — OpenAI-совместимый эндпоинт по HTTPS с авторизацией по API-ключу.
В автограде всё настроено автоматически: раннер сам поднимает GPU-VM с моделью и
ждёт её готовности. Локально задайте свой API-ключ:

```bash
export API_KEY="<ваш API-ключ>"
# опционально (есть значения по умолчанию):
export LLM_BASE_URL="https://vllm.mrsndmn.party/v1"
export LLM_MODEL="Qwen/Qwen3-4B-Instruct-2507"
```

## Запуск тестов

```bash
# Часть 1 (без ключа и сети):
PYTHONPATH=. pytest tests/test_llm_client.py

# Часть 2 — файловые тулы и agent loop (оффлайн, со скриптованным LLM):
PYTHONPATH=. pytest tests/test_tools.py tests/test_agent.py

# Все локальные тесты:
PYTHONPATH=. pytest tests/
```

### Удобный запуск через `./run_tests.sh`

GPU-VM с моделью по умолчанию **выключена** (ради экономии) и поднимается по запросу.
Скрипт `run_tests.sh` делает всё за вас: проверяет, что задан `API_KEY`, запускает VM,
дожидается готовности модели и затем прогоняет тесты.

```bash
export API_KEY="<ваш API-ключ>"
./run_tests.sh                      # все тесты (tests/)
./run_tests.sh tests/test_agent.py  # конкретный файл/папку
```

Скрипт дёрнет функцию запуска VM, подождёт, пока `${LLM_BASE_URL}/models` ответит `200`
(до ~10 минут — VM грузит модель; `401/403` означает неверный `API_KEY`), и затем
запустит `pytest`. Эндпоинт и модель берутся из `LLM_BASE_URL` / `LLM_MODEL` (см. выше).

Финальная проверка (мини-SWE-bench с реальной моделью) выполняется автоматически
на стороне `checkhw` при пуше в ваш репозиторий: CI сам поднимает GPU-VM с моделью
перед прогоном.

## Зависимости

```bash
pip install -r requirements.txt
```

GPU не требуется. Часть 1 можно сделать и проверить полностью локально; для Части 2
нужен доступ к LLM (ваш `API_KEY` к размещённой модели).

## Пожелания к процессу

Эта домашка — отличный повод воспользоваться готовыми AI-агентами (Cursor, Claude Code,
Codex, cline и т.п.), чтобы прочувствовать, как устроены инструменты, которые вы сами
сейчас собираете в миниатюре. Раздел носит рекомендательный характер.
